
[[Linux 子系统汇总]]

Linux 里“堆栈内存”要分清两套语境：**用户态进程的堆/栈**，以及 **内核态的内存分配/内核栈**。面试时最好按这两层讲。

**1. 用户态进程的虚拟地址空间**

每个进程都有独立的虚拟地址空间。典型布局：

>`高地址 
   `↓ 
>`stack 用户栈，函数调用、局部变量、返回地址 
>`mmap area mmap 映射区，共享库、匿名映射、文件映射 
>`heap 堆，malloc/new 主要使用 
>`bss/data 全局变量、静态变量 
>`text 代码段 
>`低地址`

注意：这是虚拟地址，不是一开始就全部占用物理内存。  
Linux 通常按需分配物理页，发生缺页异常时才真正建立页表映射。

---

**2. 用户态栈是怎么分配的**

用户栈由内核在创建进程或线程时设置。

进程启动时，内核会给用户态栈建立一个虚拟内存区域 VMA，通常在高地址附近。  
栈一般是**向低地址增长**。

函数调用时：

>`调用函数 
	`↓
  `压入返回地址、保存寄存器、局部变量 
	`↓
  `栈指针 SP/RSP 向低地址移动`

如果栈继续增长，访问到了尚未映射的栈区域，会触发 page fault。  
内核判断这是合法的栈增长，就分配物理页并建立映射。

可以理解为：

`先预留一段栈虚拟地址空间 真正访问时再分配物理内存`

栈大小受限制：

>`ulimit -s`

常见默认值：

>`Linux 用户栈默认常见 8MB`

线程栈：

`每个 pthread 都有自己的用户栈 
`默认大小由 pthread 库和 ulimit 等决定 
`可通过 pthread_attr_setstacksize 设置`

---

**3. 用户态堆是怎么分配的**

堆主要由 C 库的 malloc() 管理，但最终还是向内核申请虚拟内存。

常见底层机制有两个：

>`brk / sbrk： 扩展传统 heap 区域 
  `mmap： 直接创建匿名映射区域`

小块内存一般由 libc malloc 在已有 arena 中分配。  
大块内存很多实现会直接用 mmap()。

流程大致是：

`应用调用 malloc 
`↓
`glibc/jemalloc/tcmalloc 等分配器先看自己的空闲块 
`↓ 
`不够时通过 brk 或 mmap 向内核申请更多虚拟内存 
`↓ 
`真正访问时 page fault 
`↓ 
`内核分配物理页`

所以 malloc() 成功不一定表示物理内存已经全部到位，尤其在 overcommit 开启时。

---

**4. brk 和 mmap 的区别**

brk：

`扩展进程 heap 顶端 
`适合较小、连续的堆增长 
`释放给系统不灵活`

mmap：

`创建独立虚拟内存区域 
`适合大块分配 
`释放时可以 munmap 直接还给内核`

例如：

`void *p = malloc(1024); // 可能来自 brk 管理的
`heap void *q = malloc(10 * 1024 * 1024); // 可能底层用 mmap`

具体阈值由 malloc 实现决定，不是固定标准。

---

**5. 虚拟内存和物理内存的关系**

Linux 内存分配通常分两步：

`1. 分配虚拟地址空间 2. 访问时分配物理页`

示例：

`char *p = malloc(100 * 1024 * 1024);`

这一步可能只是得到虚拟地址。  
真正写入时：

`memset(p, 0, 100 * 1024 * 1024);`

才会触发缺页，逐页分配物理内存。

这就是 demand paging，按需分页。

---

**6. 内核态内存怎么分配**

内核里没有用户态那种 malloc()，常用接口是：

`kmalloc() 
`kzalloc() 
`kcalloc() 
`vmalloc() 
`alloc_pages() 
`devm_kzalloc() 
`dma_alloc_coherent()`

常见区别：

`kmalloc： 
	`分配物理连续、虚拟连续内存 适合小块内存 基于 slab/slub 分配器 
	
`kzalloc： 
	`kmalloc + 清零 
	
`kcalloc： 
	`数组分配，带溢出检查 
	
`vmalloc： 
	`虚拟地址连续，物理页不一定连续 适合大块内存 不能用于需要 DMA 物理连续的场景 
	
`alloc_pages： 
	`按页分配，返回 struct page 
	
`devm_kzalloc： 
	`设备资源管理版本，设备 detach 时自动释放 
	
`dma_alloc_coherent： 
	`分配 DMA 一致性内存，给硬件 DMA 使用`

触摸驱动里常见：

`ts = devm_kzalloc(dev, sizeof(*ts), GFP_KERNEL); 
`buf = kzalloc(size, GFP_KERNEL);`

---

**7. kmalloc 的内存从哪里来**

kmalloc() 底层一般来自 slab/slub 分配器。  
slab/slub 再从 buddy system 获取页。

层级大致是：

`物理内存 
`↓ 
`Buddy allocator 按页管理 
`↓ 
`SLAB/SLUB/SLOB 分配器管理小对象 
`↓ 
`kmalloc/kzalloc 分配给驱动`

Buddy 负责按 2^order 页分配大块页面。  
SLUB 负责把页面切成不同大小的对象池，比如 32B、64B、128B、256B、512B、1KB、2KB 等。

---

**8. GFP 标志**

内核分配内存时要传 GFP flag，表示当前上下文允许怎么分配。

常见：

`GFP_KERNEL`

含义：

`普通进程上下文使用 允许睡眠 允许内存回收 最常用`

`GFP_ATOMIC`

含义：

`中断上下文或不能睡眠的上下文使用 不能睡眠 成功率较低`

触摸驱动里：

`probe、workqueue、threaded irq 里通常可以 GFP_KERNEL 
`硬中断 handler 里不能用 GFP_KERNEL，应避免分配，必要时 GFP_ATOMIC`

但工程上更推荐：中断热路径提前分配好 buffer，不要在中断中临时分配。

---

**9. 内核栈是怎么分配的**

每个内核线程/进程在进入内核态时都有自己的**内核栈**。  
内核栈很小，常见是：

`8KB 或 16KB，取决于架构和配置`

内核栈用于：

`系统调用进入内核后的调用链 中断/异常处理上下文 局部变量 保存寄存器`

重点：

> 内核栈很小，驱动里不能在栈上放大数组。

错误示例：

`static int xxx_func(void) { u8 buf[4096]; // 风险很大，内核栈可能爆 }`

应该改成：

`u8 *buf; buf = kzalloc(4096, GFP_KERNEL); if (!buf) return -ENOMEM;`

或放到设备私有结构体里复用。

触摸驱动里读取 rawdata、firmware、flash buffer 时尤其要避免大栈数组。

---

**10. 用户栈和内核栈的区别**

`用户栈： 
	`每个用户线程一个 在用户虚拟地址空间 大小通常 MB 级 用于用户态函数调用 
`内核栈： 
	`每个 task 一个 在内核地址空间 很小，通常 KB 级 用于系统调用、中断、内核函数调用`

用户态从系统调用进入内核时，会从用户栈切换到内核栈。  
内核不能信任用户栈数据，访问用户指针要用：

`copy_from_user() 
`copy_to_user()`

---

**11. 驱动开发中的内存分配建议**

触摸屏驱动里常见建议：

`小结构体：devm_kzalloc 
`小 buffer：kzalloc/kmalloc 
`大 buffer：vmalloc 或 devm_kzalloc，视用途而定 
`DMA buffer：dma_alloc_coherent 或 dma_map_single 
`中断热路径：尽量提前分配，避免临时分配 
`大数组：不要放内核栈 
`设备资源：优先 devm_* 简化释放`

例如：

`struct ilitek_ts_data *ts; 
`ts = devm_kzalloc(&client->dev, sizeof(*ts), GFP_KERNEL); 
`if (!ts) return -ENOMEM;`

I2C 读写 buffer：

`ts->rxbuf = devm_kzalloc(dev, ILITEK_RX_BUF_SIZE, GFP_KERNEL); 
`if (!ts->rxbuf) return -ENOMEM;`

---

**12. 常见内存错误**

**栈溢出**

`u8 fw_buf[64 * 1024]; // 严重错误`

应改为动态分配。

**忘记释放**

`buf = kzalloc(size, GFP_KERNEL); return ret; // 错误路径忘记 kfree`

可用 devm_kzalloc 或统一 error path。

**use-after-free**

workqueue 没取消，remove 后 work 还访问 ts。

解决：

`cancel_work_sync(&ts->work); 
`cancel_delayed_work_sync(&ts->esd_work);`

**越界访问**

I2C 读回的数据长度没有检查，解析坐标时越界。

**错误 GFP**

硬中断里用 GFP_KERNEL 或调用可能睡眠的分配。

---

**面试版总结**

可以这样回答：

> Linux 中用户态的堆和栈都属于进程虚拟地址空间。栈一般由内核在进程或线程创建时建立 VMA，向低地址增长，按需缺页分配物理页；堆由 malloc 管理，底层通过 brk 或 mmap 向内核申请虚拟内存，真正访问时再分配物理页。内核态内存分配则使用 kmalloc、kzalloc、vmalloc、alloc_pages、dma_alloc_coherent 等接口，kmalloc 底层基于 slab/slub，slab/slub 再向 buddy system 要页。内核栈每个 task 一份，通常只有 8KB 或 16KB，很小，所以驱动里不能在栈上放大数组，触摸驱动中的 firmware buffer、rawdata buffer、I2C 大 buffer 应该动态分配，并注意 GFP_KERNEL/GFP_ATOMIC 的上下文区别。
